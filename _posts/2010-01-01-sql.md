#### 데이터베이스 (Database)

##### 계층형 DB (Hierarchical Database)
트리 자료구조에 데이터를 저장하고 관리하며 $1:N$ 관계를 표현한다

##### 네트워크형 DB (Network Database)
오너와 멤버 형태로 데이터를 저장하며 $N:M$ 관계 표현이 가능하다
 
##### 관계형 데이터베이스 (Relational Database)
관계에 데이터를 저장하고 관리하며 집합 연산 및 관계 연산을 할 수 있는 데이터베이스

##### DBMS
데이터베이스를 관리하기 위한 소프트웨어

#### 연산 (Set Algebra)

##### 집합연산
두 관계의 합

##### 교집합
두 관계에 함께 존재하는 것

##### 차집합
한 관계에만 존재하고 다른 관계에는 존재하지 않는 것

##### 곱집합
각 관계에 존재하는 모든 데이터의 조합

#### 관계 연산 (Relational Algebra)

##### 선택 연산 (Selection)
관계에서 특정 조건에 해당하는 행만 조회

##### 투영 연산 (Projection)
관계에서 특정 조건에 맞는 속성만 조회

##### 결합 연산 (Association)
여러 관계에서 공통된 속성을 통해 새로운 관계 생성

##### 나누기 연산 (Division)
기존 관계에서 나누는 관계가 가지는 속성과 동일한 행만 추출하여 중복된 행 제거

#### Structured Query Language (SQL)

##### SQL 실행 순서
1. **파싱 (Parsing)**: SQL 문법을 확인하고 구문을 분석하고, Library Cache에 저장한다.
2. **실행 (Execution)**: Optimizer가 생성한 실행 계획에 따라 SQL문을 실행한다.
3. **인출 (Fetch)**: 데이터를 읽어 전송한다.

##### 데이터 정의어 (DDL - Data Definition Language)
테이블이나 컬럼 같이 데이터 구조를 정의하기 위한 명령어

예시로는: 
- CREATE
- DROP
- RENAME
- ALTER
- TRUNCATE

##### 데이터 조작어 (DML - Data Manipulation Language)
데이터를 조회 및 검색하기 위한 명령어

예시로는:
- SELECT
- INSERT
- UPDATE
- DELETE

##### 데이터 제어어 (DCL - Data Control Language)
데이터베이스 접근 및 사용 권한을 부여하거나 회수하기 위한 명령어

예시로는:
- REVOKE
- GRANT

##### 트랜잭션 제어어 (TCL - Transaction Control Language)
트랜잭션 별로 제어하기 위한 명령어로 데이터 제어어라고도 함

예시로는:
- SAVEPOINT
- COMMIT
- ROLLBACK

#### 트랜잭션의 특징
- 원자성 (Atomicity): 데이터베이스 내 연산의 전부가 실행되거나 실행되지 않아야 한다. 트랜잭션이 완전히 끝나지 않았다면 실행되기 전의 상태와 동일하다.
- 일관성 (Consistency): 트랜잭션 결과로 데이터베이스 상태가 모순되지 않고 일관성을 유지해야 한다.
- 고립성 (Isolation): 트랜잭션 실행 중의 중간결과는 다른 트랜잭션이 접근할 수 없다.
- 영속성 (Durability): 트랜잭션이 완료되면 그 결과는 영구적으로 보장되어야 한다.

##### SELECT
테이블에 저장된 데이터를 조회하기 위한 명령어로, 특정 행 또는 컬럼을 조회할 수 있다.

```sql
SELECT country
FROM customers;
```

##### DISTINCT
SELECT절의 컬럼에 위치해 중복을 제거한 결과를 출력한다.

```sql
SELECT DISTINCT country
FROM customers

-- Returns a list of unique countries from the customers table
```



#### Bullet Points
- 관계 (Relationship)를 나타내는 세 가지 요소는 관계명 (Membership), 관계차수 (Degree / Cardinality), 관계선택사양 (Optionality)이다.


##### 주식별자
- 주식별자는 Entity를 식별할 수 있는 유일성을 만족하면서, 최소의 개수로 구성해야 한다 (최소성이라 한다).



#### 데이터베이스 이상현상 (Database Anomaly) 과 정규화 (Normalization)
모델링 되어있는 데이터베이스의 테이블과 관계들은 데이터를 입력, 수정, 삭제하는 과정에서 의도한 바와는 다르게 일관성이 깨질 수 있는데 이를 데이터베이스의 **이상현상 (Anomaly)**라고 한다. 이러한 현상을 방지하기 위해 데이터의 중복을 최소화하면서 테이블을 보다 잘 조직된 상태로 분해하는 과정을 **정규화 (Normalization)**라고 한다.

##### 삽입 이상 (Insertion Anomaly):
테이블에 데이터를 삽입할 때 의도하지 않은 정보까지 삽입해야 하는 현상

##### 갱신 이상 (Update Anomaly):
중복 저장되어 있는 데이터 중 하나만 갱신하고 다른 하나를 갱신하지 않을 때 나타나는 데이터의 불일치 현상

##### 삭제 이상 (Deletion Anomaly):
테이블의 특정 데이터를 삭제할 때 의도하지 않은 정보까지 삭제되는 현상

##### 제1 정규화:
Relation의 속성값이 모두 원자값 (Atomic Value)만으로 구성되어야 한다.
- 중복값을 제거한다.
- 기본키를 설정한다.

##### 제2 정규화:
기본키가 2개 이상의 속성으로 이루어진 경우 부분 함수종속성을 제거한다.

##### 제3 정규화:
기본키를 제외한 칼럼 간의 종속성을 제거한다. 이행 함수종속성을 제거한다.

##### BCNF (Boyce-Codd Normal Form):
기본키를 제외하고 후보키가 있는 경우 후보키가 기본키를 종속시키면 분해한다.
