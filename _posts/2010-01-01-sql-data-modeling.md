#### 데이터 모델링 (Data Modeling)

##### 데이터 모델링이란?
1. 정보시스템을 구축하기 위한 데이터 관점의 업무 분석 기법
2. 현실 세계의 데이터를 약속된 표기법으로 표현하는 과정
3. 데이터베이스 구축을 위한 분석 및 설계의 과정

##### 데이터 모델링의 특징
1. 추상화 (Abstraction): 현실 세계를 일정한 형식으로 표현해야 함
2. 단순화 (Simplification): 이러한 일정한 형식은 단순해야 함
3. 명확성 (Clarity): 이러한 일정한 형식은 명확해야 함

##### 관점
1. 데이터 관점: 
- Entity, Attribute, Relation의 중심으로 데이터 구조를 정의
2. 프로세스 관점: 
- 시스템이 어떤 기능을 수행하는지, 데이터가 어떻게 흐르는지 집중
- 작업의 순서, 조건, 규칙을 포함하여 프로세스의 흐름을 정의
3. 데이터와 프로세스의 관점:
- 데이터 구조와 프로세스의 동작이 상호작용하여 시스템을 구성하는 방식에 집중
- 어떤 영향을 미치는지에 대해서도 집중

##### 데이터 품질의 저해요소:
- 중복성 (Duplication)
- 비-유연성 (Inflexibility)
- 비-일관성 (Inconsistency)

##### 데이터모델링의 3단계:
1. 개념적 모델링 (추상화)
2. 논리적 모델링 (정규화)
3. 물리적 모델링 (DB)

##### 데이터베이스 스키마 구조:
1. 외부 (View)
2. 개념 (통합된 사용자)
3. 내부 스키마 (물리)

##### 데이터 독립성:
- 논리적 독립성
- 물리적 독립성

##### 데이터모델링의 3가지 요소
1. 엔터티 (Entity)
2. 관계 (Relation)
3. 속성 (Attribute)

##### ERD (Entity-Relation Diagram) 작성 순서:
1. 엔터티 도출
2. 배치
3. 관계 설정
4. 관계명 기술
5. 관계 차수 설정
6. 선택 사양 기술

#### 엔터티 (Entity)

##### 엔터티의 정의
업무에서 관리해야 하는 데이터의 집합, 단수명사, 인스턴스의 집합

##### 엔터티의 특징
1. 업무에서 필요로 함
2. 유일한 식별자
3. 2개 이상의 인스턴스 집합
4. 업무 프로세스에서 이용됨
5. 2개 이상의 속성
6. 관계를 가진다


#### 속성 (Attribute)

##### 속성의 정의
업무에서 필요로 하는 인스턴스에서 관리하고자 하는 의미상 더 분리되지 않는 최소의 데이터 단위

##### 속성의 특징
1. 업무에서 필요로 함
2. 주식별자에 함수적으로 종속 (기본키가 변경되면 속성도 변경)
3. 1개의 속성은 1개의 속성값을 가짐
4. 속성도 집합이다


#### 정규화
1. 제1 정규형
- 모든 속성은 반드시 하나의 값을 가져야한다 (원자성 - Atomicity)
2. 제2 정규형
- 엔터티의 일반 속성은 주식별자 전체에 종속이어야 한다 (부분 함수 종속성)
3. 제3 정규형
- 엔터티의 일반속성 간에는 서로 종속적이지 않아야 한다 (이행 함수 종속성)
4. BCNF (Boyce-Codd Normal Form)
- 후보키가 기본키 속성 중 일부에 함수적 종속일 때, 다수의 주식별자를 분리함
